# Pre-0.0.1 Hardening Spec

**Status:** Draft, awaiting user review
**Date:** 2026-05-14
**Branch:** `dev001`

## Goal

Land correctness fixes, dead-code removal, and the critical-path test additions
needed before tagging `meerkat-beams` 0.0.1. Coverage target is "critical paths
+ direct unit tests for every core function" — explicitly not "every branch of
every method".

## Non-goals

The following were considered and explicitly deferred:

- **Concurrent-download locking** (`fcntl.flock` on per-band lockfiles). The
  existing docstring caveat — "warm the cache from a single process" — stays.
  Revisit when a user actually hits a race.
- **CLI-wrapper functional tests beyond `--help`.** The CLI files are now
  fully generated by `hip-cargo >= 0.2.1` (container-dispatch, preflight
  checks, `parse_upath`, auto-injected `backend`/`always_pull_images` Typer
  params). The dispatch machinery is hip-cargo's, tested upstream. The
  cab↔cli round-trip test (B0) plus the direct core-function tests (B2) are
  the right surface to cover.
- **Trivial smoke tests** for `create_logger`, `set_console_logging_level`,
  `PowerBeam`. Low value.
- **Branch-coverage flourishes** with no realistic call-site:
  `_get_prefilter` order caching beyond default, `get_source_coordinates`
  `signs`/`swap`/explicit-`loc` variants.
- **Cab YAML regeneration.** Handled by the `generate-cabs` pre-commit hook.
  The implementer must flag if the hook fails on any commit.

### Part B — Test additions

Critical-path gaps identified by the test-coverage audit. Each bullet is a
concrete new test (or test group) to add. Existing tests stay as-is unless
called out.

#### B0. Round-trip test for hip-cargo cab ↔ cli generation

The CLI wrappers are now fully generated by `hip-cargo` (no longer thin Typer
shims). The flow is:

- `cli/*.py` → `hip-cargo generate-cabs` → `cabs/*.yml`
  (driven by the `generate-cabs` pre-commit hook; see commit `3325ae5`)
- `cabs/*.yml` → `hip-cargo generate-function` → `cli/*.py`
  (driven manually by `scripts/genfuncs.sh`)

Both directions must compose to the identity: `cli → cab → cli` should be a
no-op. Without this guarantee, any non-idempotency in `hip-cargo`, or any
manual edit in `cli/*.py` that drifts from what `hip-cargo` would emit, is a
silent regression that only surfaces the next time someone regenerates either
side.

Add `tests/test_roundtrip.py` modelled on
`/home/bester/software/pfb-imaging/tests/test_roundtrip.py`:

- In a `tempfile.TemporaryDirectory`:
  - Call `generate_cabs(module=[Path("src/meerkat_beams/cli/*.py")], output_dir=cab_dir, image=None)`
  - For each generated `cab_file`:
    - Call `generate_function(cab_file, generated_file, config_file=Path("pyproject.toml"))`
    - Assert the generated file compiles (`compile(generated_code, ...)`)
    - Compare line-by-line against the original `src/meerkat_beams/cli/<stem>.py`
- Mark `@pytest.mark.unit`. Must pass under `MBEAMS_OFFLINE=1`.

Failure mode this pins: someone hand-edits `cli/*.py` (e.g. to "fix" a Typer
quirk) without updating the cab, or vice-versa; the pre-commit hook and the
manual regen script disagree about what the canonical form is. The test fires
immediately on either kind of drift.

#### B1. `utils.py` — `BeamWizard` and helpers

- **`enrich_bds_xradio` (currently zero tests).** Build a tiny synthetic zarr
  via `get_time_freq_beam`, run `enrich_bds_xradio` on it, then assert:
  - `l` and `m` coords converted degrees → radians
  - `polarization` labels rewritten (`"II"` → `"I"` etc.)
  - `direction` attr block present with `icrs`, SIN projection, reference =
    field centre
  - Metadata re-consolidated (zarr `.zmetadata` present and parseable)
- **`get_time_freq_beam` coverage expansion.**
  - Alternative `dim_names` permutation (e.g. `("frequency", "time", "polarization", "l", "m")`)
    — pins axis-mapping correctness for both `ij_axis` and `time_axis`.
  - `ij_list` with two elements (e.g. `[("I", "I"), ("Q", "Q")]`).
  - `pixel_stepping=2` (exercises the upsample branch via linear
    `map_coordinates`).
  - **Regression test for A1**: re-open the rendered zarr with default
    `xarray.open_zarr` (no `mask_and_scale` flag) and assert that `l=0.0` /
    `m=0.0` coords are real zeros, not NaN.
- **`_resolve_freqs` direct tests.**
  - Both `freq` and `num_freq` passed → `ValueError`.
  - `spi != None` weighting normalises to 1.0 across the returned weights.
- **`get_time_variable_beamgain` — `spi` branch.** Compare two calls with the
  same coord/time but `spi=None` vs `spi=-0.7`; assert shapes and that the spi
  branch returns a scalar per time (frequency-averaged) while `spi=None`
  returns one value per frequency.
- **`get_rotation_averaged_beam` — 2D inputs.** Pass `l`, `m` as matching 2D
  arrays of shape `(3, 5)`; assert output shape matches. Pass mismatched 2D
  shapes; assert `ValueError`.
- **`interpolate_beam` — non-default `var`/`(i, j)`.** Add one `var="jones"`
  case with `(i, j) = ("0", "1")` and one Stokes case with
  `(i, j) = ("Q", "I")`; just confirms the i/j label-to-index lookup works
  (output values are not asserted beyond "finite & correct shape").

#### B2. `core/*.py` — direct unit tests

Each core module currently has only a `--help` smoke test (except
`mdv_beams_to_bds`, which has an env-gated integration test). The next bullets
describe new hermetic unit tests, written against the plain-Python core
function, that monkeypatch any I/O.

- **`core/download_mdv_beams.py`.** Build a `tests/test_download_mdv_beams.py`
  file that monkeypatches the downloader (the module uses `wget`; the simplest
  mock target is the package-level symbol the core function imports). Cover:
  - `source` = full URL → downloads from that URL exactly once.
  - `source` = bare filename → downloads from `base_url + filename`.
  - `source` = band code (`"L"`) → resolves to the canonical SARAO filename.
  - `source` = unrecognised string → `ValueError` (or whatever the current
    branch raises; if it currently `sys.exit`s, change to raise + assert).
  - Mirror loop: first mirror raises `HTTPError`, second succeeds → exactly one
    file lands on disk.
  - `exit_on_error=None` → raises on total failure; `exit_on_error=2` → calls
    `sys.exit(2)`. Use `pytest.raises(SystemExit)`.
- **`core/mdv_beams_to_bds.py` additions.** Existing parametrised integration
  test stays. Add:
  - NPZ branch hermetic test: synthesise a tiny `.npz` matching the MdV schema
    (`beam`, `freq_MHz`, `margin_deg`, `pols`, `antnames`) in `tmp_path`; run
    the core function with `compress=False`; assert the resulting BDS has
    expected `jones`/`njones`/`stokes`/`nstokes` shapes and the synthesized
    `fits_header` is in `.attrs`.
  - `compress=True` path: same input as above, just verify the resulting zarr
    `.zarray` blocks include the Blosc compressor (no value comparison).
- **`core/bds_to_xradio.py`.** Validation error branches first (hermetic, no
  rendering):
  - Invalid `beam_type` → `ValueError`.
  - `elements` shape mismatch with `beam_type` → `ValueError`.
  - `output_pol` length ≠ rendered polarization axis length → `ValueError`.
  Plus one minimal end-to-end run using the cached L-band BDS (already warmed
  by `conftest.pytest_sessionstart`) and a synthetic image with a 2-time WCS,
  asserting the output zarr is xradio-shaped. Marked `@pytest.mark.integration`
  so air-gapped CI can skip via `MBEAMS_OFFLINE=1`.
- **`core/mdv_to_xradio.py`.** Build a synthetic NPZ and run the core function
  for:
  - Each `part` ∈ `{"real", "imag", "abs", "phase"}` → checks the
    `part`-dispatch branch end-to-end.
  - `antenna=-1` (default, array_average) and one specific antenna index.
  - One `jones` element from each of `{"HH", "HV", "VH", "VV"}`.
  - Invalid `part="bogus"` → `ValueError`.

## Failure modes the new tests pin

| Hypothetical regression | Pinned by |
|---|---|
| `cli/*.py` and `cabs/*.yml` drift (manual edit, hip-cargo non-idempotency, partial regen) | B0 round-trip test |
| Someone reintroduces `fill_value=0` and rendered zarrs ship NaN-corrupted | A1 regression test in B1 |
| `_get_prefilter` cache silently grows to float64 again | B1 (assertion on cached array dtype) |
| `get_time_freq_beam` axis-mapping breaks when `dim_names` is reordered | B1 permutation test |
| `enrich_bds_xradio` drops the `direction` attr or skips polarization renaming | B1 |
| Adding a new mirror to `download_mdv_beams` breaks the fallback loop | B2 HTTPError-fallback test |
| `mdv_beams_to_bds` NPZ parsing breaks without the integration test running | B2 NPZ branch test |
| Someone tightens `bds_to_xradio` input validation and accidentally accepts garbage | B2 validation tests |

## Dependencies and assumptions

- **`hip-cargo >= 0.2.1`** is pinned in `pyproject.toml` (commit `d16dbef`).
  Earlier versions emit a different CLI shape and the round-trip test (B0)
  would diff against them.
- **`generate-cabs` pre-commit hook** regenerates `cabs/*.yml` from `cli/*.py`
  on every commit (commit `3325ae5`). If it fails on any commit, the
  implementer pauses and asks. Don't `--no-verify`.
- **`scripts/genfuncs.sh`** regenerates `cli/*.py` from `cabs/*.yml`. This is
  the manual counterpart to the pre-commit hook; the round-trip test pins
  that the two are inverses.
- **L-band BDS is pre-warmed** by `tests/conftest.py::pytest_sessionstart`
  unless `MBEAMS_OFFLINE=1`. The one end-to-end test in B2.3 relies on this.
- All hermetic tests must be marked `@pytest.mark.unit` and run without
  network. The single integration test in B2.3 is `@pytest.mark.integration`.

## Out of scope (for completeness)

- Concurrent-download lock (deferred).
- Trivial logging/dataclass smoke tests.
- CLI-wrapper functional tests beyond `--help`.
- Re-engineering the cab YAML build flow.
- Improvements to `BeamWizard.interpolate_beam` accuracy beyond the meshgrid
  cleanup.

## Acceptance criteria

1. `uv run pytest -m unit -v` passes locally with all new tests.
2. `uv run ruff check .` and `uv run ruff format --check .` pass.
3. `MBEAMS_OFFLINE=1 uv run pytest -m unit -v` passes (no network).
4. Test count strictly increases — no test deletions except the existing
   `mask_and_scale=False` workaround in `test_time_freq_beam_writes_zarr`,
   which becomes obsolete after A1.
5. CLAUDE.md "Still open" section is empty after this lands (or contains only
   the explicitly deferred items).
6. README reflects the current `BeamWizard(band=...)` API and cache layout.
